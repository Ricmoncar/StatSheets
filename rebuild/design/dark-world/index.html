07

DESIGN NOTES

Enough to build it. The atlas script on this page is the reference implementation: every sprite is a grid of palette keys, rendered once to canvas and handed to CSS.

1. THE GRID

  • 1 art pixel = --px: 3 CSS px from 641 px wide, 2 CSS px on phones. Nothing else changes between the two.
  • Every border, gap, padding, icon and sprite is a whole number of art pixels: calc(n * var(--px)). Spacing steps: 1, 2, 3, 4, 6, 8, 12.
  • Sprites are authored at 1x as grids of palette keys and rendered at --px x devicePixelRatio with smoothing off, so a 2x screen still gets whole device pixels.
  • image-rendering: pixelated on everything. No blur, no soft shadow, no smooth gradient: hard shadows, Bayer 4x4 dither and banded ramps only.
  • Text is held to the same rule: only sizes that measure crisp (see 06). Acceptance test: count the distinct colours in a screenshot; anti-aliasing shows up as hundreds.

2. PALETTE TOKENS

32 fixed colours plus a 6-step accent ramp. The ground is pure void. Sprites refer to colours by one-letter keys; CSS by --c-* and --a0 to --a5.

Live accent ramp (from the accent picked above):

Fixed meanings: SOUL red is you and danger, yellow is selected and HP, KR magenta is prestige, green is a bonus. Stat colours mark stat icons and modifiers, never the bars.

3. FRAMES (9-SLICE)

PANEL FRAME, ZOOMED. GOLD LINES = SLICES

A frame is a profile (ring colours from the outside in, optionally split into lit top-left and shaded bottom-right), a chamfer, a hard drop shadow with its colour, and an optional corner ornament. The generator draws a (2C+1) square, so the middle row and column are uniform and stretch without ever scaling a pixel pattern; the corners carry the detail.

// one entry per frame; C = max(rings, chamfer, ornament)
panel:  { p:['k','3','3','1'], n:2, sh:2, shc:'1', f:'k', o:GEM }
btn:    { p:['k','3','k'], n:1, sh:1, shc:'1', f:'k' }
dialog: { p:['k','w','w','w'], n:0, f:'k' }  // the Undertale box
// CSS it emits (geometry once, source per accent)
border-width: 18px 24px 24px 18px;
border-image: url(panel.png) 18 24 24 18 fill / 18px 24px 24px 18px / 0 stretch;

Which frame a new component gets: if it talks to you or floats (dialogue, modal, tooltip, menu, toast, select list) it is the square white box. If it holds content it is an accent panel, chamfered, with an accent shadow. If you press it, it is a button frame. If you type in it, it is a sunken well. Rarity frames are the only fixed-colour frames.

Pressed states are the same sprite drawn one shadow-width down-right with no shadow, so content drops exactly 1 art px. Palette-cycled frames (epic, mythic, hexxed, equipped) swap border-image-source on a step-end timeline.

4. ANIMATION RULES

KINDRATEHOW
Sprite loops (coin, star, eq, SOUL)6 to 10 fpsSheet + steps(n) on background-position
Card art windows6 to 10 fps6 to 12 drawn frames per rarity
Palette cycling (rims)4 to 10 fpsFrame swap with step-end
Backgrounds10 fps tickCanvas at art resolution; far layer 1 px / 4 ticks, mid 1 / 2, near 1 / 1

Never ease pixel art. Colour changes are instant. Transforms only ever move by whole art pixels. Looping motion may only touch paint properties (background position, border-image source, clip-path, transform), never width, height or text, so a loop costs a repaint and no layout.

5. ACCENT RECOLOURING

  1. Accent hex to HSL. Greys stay grey; anything else gets a saturation floor of 60% so the ramps stay rich.
  2. Six steps at fixed lightness bands (9, 18, 31, accent, 72, 88%). Shadows hue-shift toward indigo (250 deg) by 40 / 25 / 12%, highlights toward yellow (55 deg) by 10 / 18%. That is the pixel-art ramp rule, done in code.
  3. --a0 to --a5 go on :root; --on-a flips to void or white by luminance so text on accent fills always reads.
  4. The atlas is split in two. The static sheet (icons, rarity frames, card art, cursors, frame geometry) is built once per grid size. The accent sheet holds only the sprites, frames and textures that use keys 0 to 5, as image sources and variables, so a swap repaints but never relayouts.
  5. Accent sheets are cached by colour. Clicking around the sidebar reuses them; last change: no change yet.
  6. One-colour UI icons are CSS masks filled with a token, so they recolour with zero JS.
  7. Rarity, stat, gold and SOUL colours never recolour: they are meaning, not theme.

6. PERFORMANCE + MOTION

  • PERF mode (toggle at the top): the background engine draws one frame and stops; card rims and art freeze on frame 0; foil, shimmer and jitter stop. Elements marked .keep (loading star, bar, coin, player) still run because they carry meaning.
  • prefers-reduced-motion (or the REDUCE MOTION toggle): animations end on their final frame instead of pausing, scenes are static, typewriter prints instantly, no shake, dice land at once.
  • Off-screen work stops: canvases skip ticks (IntersectionObserver), sections out of view get .idle which pauses their CSS loops, and the roll demo only replays while visible.
  • Panels are contain: content, and text that changes at runtime sits in size-contained boxes, so nothing relayouts the page. There is no CSS multicol: it re-balanced on every change.
  • Measured in headless Chromium at 1920 px with the mockup on screen: 15 to 24% of one core, about 1 ms of layout a second. An accent change: 12 to 36 ms of script, 57 to 90 ms to the next frame. One shared 10 fps clock drives every scene. Live now: updates while visible
