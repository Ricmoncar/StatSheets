06

DESIGN NOTES

Enough to build it. The atlas script on this page is the reference implementation: every sprite is a grid of palette keys, rendered once to canvas and handed to CSS.

1. THE GRID

  • 1 art pixel = --px: 3 CSS px from 641 px wide, 2 CSS px on phones. Nothing else changes between the two.
  • Every border, gap, padding, icon and sprite is a whole number of art pixels: calc(n * var(--px)). Spacing steps: 1, 2, 3, 4, 6, 8, 12.
  • Sprites are authored at 1x as grids of palette keys and rendered at --px x devicePixelRatio with smoothing off, so a 2x screen still gets whole device pixels.
  • image-rendering: pixelated on everything. No blur, no soft shadow, no smooth gradient: hard shadows, Bayer 4x4 dither and banded ramps only.
  • Text is the one exception: fonts are pixel faces at sizes that land on 2 px glyph blocks.

2. PALETTE TOKENS

32 fixed colours plus a 6-step accent ramp. Sprites refer to them by one-letter keys; CSS by --c-* and --a0 to --a5.

Live accent ramp (from the accent picked above):

3. FRAMES (9-SLICE)

PANEL FRAME, ZOOMED. GOLD LINES = SLICES

A frame is a profile (ring colours from the outside in, optionally split into lit top-left and shaded bottom-right), a chamfer, a hard drop shadow and an optional corner ornament. The generator draws a (2C+1) square, so the middle row and column are uniform and stretch without ever scaling a pixel pattern; the corners carry the detail.

// one entry per frame; C = max(rings, chamfer, ornament)
panel: { p:['k','w','w','k',['4','2']], n:2, sh:2, f:'n', o:GEM }
btn:   { p:['k','3','k'], n:1, sh:1, f:'n' }
dialog:{ p:['w','w','w'], n:0, f:'k' }   // the Undertale box
// CSS it emits
border-width: 18px 24px 24px 18px;
border-image: url(panel.png) 18 24 24 18 fill / 18px 24px 24px 18px / 0 stretch;

Pressed states are the same sprite drawn one shadow-width down-right with no shadow, and the slices shift with it, so content drops exactly 1 art px. Palette-cycled frames (epic, mythic, hexxed, equipped) swap border-image-source on a step-end timeline.

4. ANIMATION RULES

KINDRATEHOW

Never ease pixel art. Colour changes are instant. Transforms only ever move by whole art pixels.

5. ACCENT RECOLOURING

  1. Accent hex to HSL. Greys stay grey; anything else gets a saturation floor of 60% so dark-world ramps stay rich.
  2. Six steps at fixed lightness bands (9, 18, 31, accent, 72, 88%). Shadows hue-shift toward indigo (250 deg) by 40 / 25 / 12%, highlights toward yellow (55 deg) by 10 / 18%. That is the pixel-art ramp rule, done in code.
  3. --a0 to --a5 go on :root; --on-a flips to void or white by luminance so text on accent fills always reads.
  4. The atlas re-renders every sprite, frame and texture that uses keys 0 to 5 (about 0.1 s, once per change) and swaps one injected stylesheet. Canvas scenes reinit their cached layers.
  5. Rarity, stat and SOUL colours never recolour: they are meaning, not theme.

6. PERFORMANCE + MOTION

  • PERF mode (toggle at the top): the background engine draws one frame and stops; card rims and art freeze on frame 0; foil, shimmer and jitter stop. Elements marked .keep (loading star, bar, coin, player) still run because they carry meaning.
  • Static textures and frames cost nothing either way: they are small PNG data URLs generated once.
  • prefers-reduced-motion (or the REDUCE MOTION toggle): all CSS animation off, scenes static, typewriter prints instantly, no shake, dice land at once.
  • Offscreen canvases stop ticking (IntersectionObserver). One shared 10 fps clock drives every scene.
  • Measured here: about 0.5 ms per tick for the sheet scene, 1 to 2 ms with all six scenes on screen. One stylesheet swap per accent change. Live now: waiting
